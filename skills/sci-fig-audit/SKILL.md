# sci-fig-audit：投稿前配图自查

> 目标：投稿前把"编辑部一眼打回"的问题全部提前消灭。
> 核心纪律：**脚本先行、人工补位；blocker 清零才可投；为清零改规则是作弊。**

## 1. 何时使用

- 图表生成完毕、准备投稿或返修提交时 → 必须跑完本 skill
- `/lhg-sci-figure:audit` 命令全程按本 skill 执行
- 团队内互相审图时 → 用第 5 节清单做评审表

## 2. 输入与输出

- **输入**：绘图脚本目录（默认 `figures/`）+ 目标期刊规范卡
- **输出**：`figures/audit-YYYYMMDD.md` 分级审计报告，结论为"可投 / 不可投"

## 3. 确定性脚本审计（机器部分，零 LLM 成本）

```bash
python3 scripts/audit/figure_audit.py --target figures/ --format text
```

脚本扫描绘图脚本（Python matplotlib / seaborn / plotnine 风格），规则分三级：

- **blocker**（必须修，否则投稿大概率被打回）：
  - FIG-DPI-001：位图导出 DPI < 300
  - FIG-SUB-001：子图编号跳号（如 (a)(c) 缺 (b)）
  - FIG-LEG-001：多数据系列无图例
  - FIG-AXL-001：坐标轴标签缺失
- **warning**（修或写豁免理由）：
  - FIG-FNT-001 字体未声明 / FIG-LWD-001 线宽过细 / FIG-CMY-001 色彩模式未声明
  - FIG-VEC-001 只有位图无矢量主件 / FIG-UNT-001 坐标轴缺单位
  - FIG-RNG-001 随机种子缺失 / FIG-PTH-001 绝对路径硬编码
  - FIG-SIZ-001 画布超栏宽 / FIG-TLE-001 图内标题 / FIG-CBL-001 红绿配色
- **nit**（顺手修）：刻度/网格/编号顺序/数据另存等细节

发现分三级处理：blocker 逐条修（修一条复查一条）；warning 修掉或写豁免理由；nit 顺手修。

## 4. blocker 修复手册（最常见的四种打回原因，怎么修）

### 4.1 FIG-DPI-001：位图 DPI 不足

- 根因：`savefig("fig.png")` 没传 dpi，默认 100，直接投稿等于自杀。
- 修复：`savefig("fig.png", dpi=600)`；同时补上 `savefig("fig.pdf")` 矢量主件。
- 验证：重跑脚本，规则消失；用图片查看器按实际打印尺寸预览，字不糊。

### 4.2 FIG-SUB-001：子图编号跳号

- 根因：删子图时忘了重编号，或复制粘贴时编号没改。
- 修复：全局搜索 `(a)` `(b)` `(c)`，按阅读顺序重排；编号用脚本变量生成而不是手写。
- 验证：规则消失；人工看一眼编号顺序是左→右、上→下。

### 4.3 FIG-LEG-001：多数据系列无图例

- 根因：画了两条线只给了一条 label，或 legend() 调用被注释掉了。
- 修复：每个数据系列给 `label=`，末尾调一次 `legend(frameon=False)`；图例放数据空白处，不遮挡曲线。
- 验证：规则消失；把图缩到栏宽，图例字可读且与曲线一一对应。

### 4.4 FIG-AXL-001：坐标轴标签缺失

- 根因：探索性画图时随手画的，没补标签。
- 修复：`set_xlabel("时间（min）")` / `set_ylabel("浓度（μM）")`，标签必须带单位。
- 验证：规则消失；FIG-UNT-001（单位）同步检查通过。

通用修复纪律：一次只修一条，修完重跑脚本；修的过程中发现规范卡本身过时（如期刊改了要求），先更新规范卡再改图。

> 经验值：一张投稿图平均要过 2-3 轮"脚本+人工"循环才干净。第一轮修 blocker，
> 第二轮修 warning，第三轮做人工可读性评审。想一轮过关的，往往返修时加倍奉还。

## 5. 分级定义

| 级别 | 含义 | 处置 |
|---|---|---|
| blocker | 投稿后大概率被编辑部/审稿人打回的问题 | 必须修，不接受豁免 |
| warning | 规范建议，多数期刊希望你做到 | 修掉，或写一句话豁免理由 |
| nit | 细节打磨 | 顺手修，不阻塞 |

## 5. 人工评审清单（脚本抓不到的，人来审）

### 5.1 可读性（把图缩到实际栏宽看）
- [ ] 最小的字在栏宽下可读吗？（打印或按实际尺寸预览）
- [ ] 图例与数据线能一一对应吗？线型/颜色在小尺寸下分得清吗？
- [ ] 误差棒/置信带在小尺寸下还看得见吗？

### 5.2 科学诚实性
- [ ] 纵轴截断了吗？截断处有明确标识吗？
- [ ] 误差棒类型（SE/SD/CI）在图注写清了吗？
- [ ] 显著性标注的检验方法写了吗？多重比较校正了吗？
- [ ] 样本量 n 标注了吗？（箱线图/柱状图必须）

### 5.3 规范一致性
- [ ] 子图编号阅读顺序是左→右、上→下吗？
- [ ] 全图只有一种字号、一种字体家族吗？
- [ ] 配色跨图一致吗？（同一研究的系列图）
- [ ] 色彩模式与期刊要求一致吗？（RGB 在线 / CMYK 印刷）

### 5.4 可复现性
- [ ] 绘图脚本 + 数据文件都在吗？换台机器能跑出来吗？
- [ ] 随机种子固定了吗？依赖版本记录了吗？
- [ ] 数据文件是原始数据的可追溯版本吗？（处理步骤写清了吗？）

## 6. 审计报告模板

```markdown
# 配图审计报告（2026-10-11）
- 目标期刊：____ ｜ 规范卡版本：v1.0
- 脚本审计：blocker X / warning Y / nit Z（详见附表）
- 人工评审：5.1 □通过 □不通过；5.2 □通过 □不通过；5.3 □通过 □不通过；5.4 □通过 □不通过
- 需人工确认项：（期刊特殊要求与默认规范冲突处）
- 结论：可投 / 不可投
```

结论只能是"可投"或"不可投"，不许写"基本没问题"。

## 7. 反模式

1. **只跑脚本不看图**：脚本查的是代码规范，图丑、误导、讲不清故事只能人看出来。
2. **截图式自查**：把屏幕截图发给别人审，分辨率和尺寸全失真，必须审矢量/高清位图。
3. **warning 全豁免**：豁免理由写"懒得改"等于没审，豁免必须是一句话的真实理由。
4. **修完不复查**：修一条，用脚本复查一条，再人工看一眼，三步缺一不可。

## 8. 自检与反馈

质检门（审计阶段）：
- [ ] 脚本跑了吗？blocker 清零了吗？
- [ ] 人工清单 5.1-5.4 逐项打勾了吗？
- [ ] 报告存档了吗？结论是二选一的"可投/不可投"吗？
- [ ] 豁免项都有真实理由吗？

标准冒烟用例：用 fixtures/fig-bad 跑脚本，FIG-DPI-001 / FIG-SUB-001 / FIG-LEG-001 / FIG-AXL-001 四个 blocker 必须全部命中。

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-sci-figure/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
