# sci-fig-plan：学术配图方案规划

> 目标：动手画图之前，先回答三个问题——这张图要证明什么？给谁看（哪个期刊）？由几个子图讲完？
> 核心纪律：**没有规范卡不画图，没有 panel plan 不做多面板。**

## 1. 何时使用

- 用户说"帮我画个图"、"把这组数据可视化"时 → 必须先跑本 skill 定规范卡和图型
- 要做多面板组合图（2 个子图以上）时 → 必须先出 panel plan 并经用户确认
- 期刊/会议/学位论文对配图有明确格式要求时 → 先用规范卡把要求翻译成绘图参数
- 用户已经给了明确的图型和期刊要求 → 可跳过第 2 步，直接做第 3-4 步

## 2. 输入与输出

- **输入**：原始数据（文件/表格/描述）+ 研究问题（一句话：这张图要支撑哪个结论）+ 目标期刊（可空）
- **输出**：`figures/figNN_plan.md`，包含：故事线、规范卡、图型选型、panel plan（如有）、数据清单

## 3. 第一步：定故事线（最多 3 个问题）

### 3.1 提问原则

1. **先问结论，再问数据**：图是为结论服务的。不知道图要支撑哪个结论，就不知道该突出什么。
2. **一次只问最关键的**：按"结论 → 对比 → 期刊"的顺序问，3 个问题封顶。
3. **不替用户做科学判断**：哪个组显著、数据要不要对数变换，这类判断问用户，不许脑补。

### 3.2 必问清单（按需取用，不超过 3 个）

1. **讲什么故事？**——"这张图要支撑论文里的哪个结论？一句话。"
   → 决定图型选型和视觉强调点（要突出的组/趋势）。
2. **跟谁比？**——"读者要从这张图里看出什么对比或关系？"
   → 决定是否需要多组并列、误差棒、显著性标注。
3. **投哪里？**——"目标期刊/会议是？有配图格式要求吗？"
   → 决定规范卡（栏宽/DPI/字体/色彩模式）。

### 3.3 停止条件

- 3 个问题问完，或用户说"就这样，开始吧" → 进入第二步。
- 用户只想要探索性看图（不投稿）→ 走简化流程：只做第 4 步的宽松版规范卡。

## 4. 第二步：写规范卡（把期刊要求翻译成参数）

规范卡是后续所有绘图脚本的"宪法"，格式如下：

```markdown
## 规范卡 fig01（目标：Nature 通讯类）
- 栏宽：单栏 89 mm → figsize=(3.5, 2.6) in
- DPI：位图 600，矢量 PDF 为主件
- 字体：Arial，通栏字号 7pt（轴标签/刻度/图例统一）
- 线宽：主线 1.0pt，辅助线 0.5pt
- 配色：离散 4 色（色盲友好，避免红绿直配）
- 子图编号：(a)(b)(c)，左上起按行排列
- 导出：fig01.pdf（矢量主件）+ fig01.png（600 dpi 预览）
- 色彩模式：RGB（在线）/ 转 CMYK（印刷前）
```

关键换算（记死）：
- 1 in = 25.4 mm；单栏 85-89 mm ≈ 3.35-3.5 in；双栏 180-183 mm ≈ 7.1-7.2 in
- 期刊常用字号 7-9pt；线宽 0.75-1.5pt；位图投稿至少 300 dpi，线图建议 600 dpi

## 5. 第三步：图型选型（数据决定图型，不许反着来）

| 研究问题 | 首选图型 | 禁忌 |
|---|---|---|
| 组间比较（均值±误差） | 柱状图/点图 + 误差棒 | 不用折线连分类轴 |
| 趋势/时间序列 | 折线图（多组用不同线型+颜色） | 不用柱状图画连续趋势 |
| 分布形态 | 箱线图/小提琴图/直方图 | 样本量<10 不用箱线图装样子 |
| 相关性 | 散点图（+回归线/置信带） | 不用双 Y 轴暗示相关 |
| 矩阵/多维 | 热图（+数值标注阈值） | 色标必须连续、无跳变 |
| 占比 | 堆叠柱（类别<6），不用饼图 | 饼图超过 5 块一律否决 |

多面板规则：
- 一个子图只讲一件事；子图超过 4 个先问用户能不能拆成两张图
- 子图编号连续 (a)(b)(c)…，阅读顺序左→右、上→下
- 所有子图共享同一套字体/字号/线宽/配色（规范卡约束）

## 6. 第四步：panel plan（多面板必备）

```markdown
## panel plan fig02（2×2，共 4 子图）
- (a) 折线图：三组药物的时间-效应曲线，突出 A 组显著性
- (b) 柱状图：终点均值±标准误，标注 * p<0.05
- (c) 散点图：剂量-效应相关性
- (d) 热图：基因表达矩阵（行标准化）
```

panel plan 必须经用户确认后才能进入绘图阶段。

## 6.5 数据清单（动手前的数据体检）

画图前先确认数据本身没问题，否则图越漂亮误导性越强：

- [ ] 数据是原始数据还是处理过的？处理步骤（去噪/归一化/剔除异常值）记录了吗？
- [ ] 缺失值怎么处理的？（删除/插补/保留，方法要写进图注或方法节）
- [ ] 样本量 n 对每组都标注了吗？组间 n 差异大时要在图注说明
- [ ] 单位统一了吗？（ms vs s、μM vs nM 混用是返修重灾区）
- [ ] 有没有"看起来不对"的点？先跟用户确认是真实信号还是录入错误，不许悄悄删点

数据有硬伤时：先停下来跟用户说清楚，提供"修正数据后重画"的选项，不许用好看的图掩盖脏数据。

### 6.6 探索性看图 vs 投稿图（分流）

- **探索性看图**（自己看、组会讨论）：规范卡可简化为"字号可读 + 有轴标签 + 有图例"三项，
  允许默认配色、允许位图直出，目标是快。
- **投稿图**：规范卡 8 项全填、多面板要有 panel plan、必须过脚本审计 + 人工评审。
- 分流纪律：探索性图**不许**直接拿去投稿。想投稿就按投稿流程重走一遍（多花 20 分钟，
  省掉一轮返修）。

> 一句话总结规划阶段：先定故事（讲什么），再定规范（给谁看），再定图型（怎么讲），
> 最后体检数据（讲的东西站得住吗）。四步走完，画图只是体力活。
>
> 规划文档存 `figures/figNN_plan.md`，与绘图脚本、数据文件放在同一目录，方便追溯。

## 7. 反模式（这些做法一律否决）

1. **先画再定规范**：画完才发现栏宽超了，返工重画。规范卡是第一步。
2. **一张图讲三个故事**：信息过载等于没有信息，拆图。
3. **双 Y 轴**：99% 的情况下是在误导读者，用分面板或标准化代替。
4. **彩虹配色/红绿直配**：色盲读者直接出局，用色盲友好配色。
5. **图内大标题**：caption 写在正文里，图里不放标题（期刊普遍要求）。
6. **截图当配图**：位图截图放大即糊，必须由脚本重新生成矢量图。

## 8. 自检与反馈

质检门（规划阶段）：
- [ ] 故事线一句话能说清吗？说不清 → 回第 3 步
- [ ] 规范卡 8 项填全了吗？（栏宽/DPI/字体/线宽/配色/编号/导出/色彩模式）
- [ ] 图型选型在第 5 步表里有依据吗？特例要写理由
- [ ] 多面板有 panel plan 且用户确认了吗？

标准冒烟用例：给一组"三组药物终点比较"数据，规划输出应包含规范卡 + 柱状图选型 + 误差棒要求。
